# AXIS Product Model

本 Skill 是 AXIS 开发的核心产品概念基础。开发 AXIS 的前端、后端、配置模型、API、文案、线路编排、发布能力、虚拟网口或节点来源相关任务时，必须先遵守这里的模型。

## 核心定位

AXIS 是一个代理来源聚合、线路编排、本机使用和对外发布的一体化工具。

默认产品模型：

```text
节点来源 → 线路组合 → 使用 / 发布
```

不要把订阅、单代理、本机节点、其他 AXIS、出口线路、中转线路、本地代理做成互相割裂的产品孤岛。

## 默认信息架构

主导航优先采用：

```text
使用
线路
发布
运行
系统
```

职责边界：

- `使用`：让这台设备现在就能通过代理访问网络，包括普通本地代理和虚拟网口。
- `线路`：管理所有节点来源，并组合流量路径，包括订阅、单代理、其他 AXIS、本机节点、初始代理和落地出口。
- `发布`：把已有线路生成给浏览器、应用或其他 AXIS 使用的连接，并配置认证。
- `运行`：查看代理核心状态、连接状态、错误原因和操作记录。
- `系统`：管理密码、核心版本、高级配置、宿主集成。

禁止默认恢复为 `订阅与节点 / 出口线路 / 中转线路 / 本地代理 / 本机节点 / 运行状态 / 操作记录` 等技术对象并列的主导航结构。

## 核心概念

### 上游模式与本体模式

AXIS 处理节点时必须区分两种模式：

- 上游模式：节点来自订阅、单个代理或其他 AXIS。AXIS 负责导入、保真保存、定时同步、健康检查、线路选择和再次发布，不主动重新设计伪装参数。
- 本体模式：节点由当前设备创建。AXIS 负责生成协议服务、认证、端口、域名/证书关联、宝塔/nginx 适配、可达性检查和对外连接信息。

上游模式的关键不是简化字段，而是不要破坏上游已经给好的连接参数。本体模式才需要 AXIS 把 Trojan、Hysteria2 等协议需要的域名、证书、SNI、TCP/UDP 可达性做完整。

### 节点来源

节点来源表示 AXIS 可以拿来编排线路的节点从哪里来，包括：

- 订阅
- 单个代理
- 其他 AXIS 发布的连接
- 本机创建的节点

本机节点属于节点来源，不作为独立业务孤岛。协议类型只是节点来源的属性，Trojan、Hysteria2 等能力应在创建或编辑节点来源时配置。

### 线路组合

线路组合表示流量具体怎么走，包含：

- 初始代理
- 落地出口
- 自动选择
- 顺序容灾
- 健康检查
- 中转组合

线路组合规则必须有唯一归属点，不得在使用页、发布页或其他页面重复实现。

### 使用

使用表示这台设备自己怎么通过 AXIS 上网，包括：

- 本机 HTTP/SOCKS 代理地址
- 本机虚拟网口代理
- 当前使用线路
- 当前节点
- 一键复制代理地址
- 一键应用当前配置
- 快速切换线路
- 连接异常提示和修复动作

使用页是日常入口，只消费线路结果，不重新定义线路。

### 发布

发布表示把已有线路提供给外部使用，包括：

- HTTP 代理入口
- 订阅链接
- 其他 AXIS 可导入连接
- 账号密码或等价认证
- 访问范围
- 启停和复制连接信息

发布页只包装线路结果，不负责创建节点来源或重新编排线路。对外使用默认必须认证，不要把无认证发布作为默认路径。

## 默认用户流程

首次使用时，不要求用户理解所有概念。AXIS 应引导用户完成最短路径：

```text
添加节点来源 → 创建推荐线路 → 选择本机使用方式 → 开始使用
```

发布给外部使用的路径：

```text
添加节点来源 → 创建线路 → 发布给其他设备或其他 AXIS
```

本机作为节点的路径：

```text
创建本机节点 → 加入节点来源 → 组合线路 → 发布或本机使用
```

## 开发约束

- 同一语义只能有一个归属点。
- 上游模式必须保留原始节点能力和伪装参数，不得只保存最小连接字段。
- 导入订阅后如果发现当前解析或发布规则会丢失协议字段，必须提示风险，并允许生成可测试的适配建议，不得把兼容成本默认转嫁给用户手工处理。
- 本体模式必须由 AXIS 生成可用配置和检查结果，不得把核心配置责任转交给用户手动拼接。
- 订阅源必须支持定时同步、手动同步、失败触发同步和上次成功快照兜底。
- LLM 只能参与协议适配建议、规则草案生成和测试说明，不得直接修改运行时代码或直接启用新规则。
- LLM 输出必须是 AXIS 可消费的结构化草案，AXIS 根据草案生成配置、模板、规则或测试项，不要求用户手工照抄配置。
- LLM 调用优先支持流式输出，但流式过程只用于展示分析进度，最终必须产出完整结构化结果并通过 AXIS 校验后才能测试或确认。
- LLM 生成的协议适配规则必须先进入待测试状态，用户测试通过并确认后才能固化启用。
- 自然语言出口规则必须被编译为 AXIS 固定规则后执行，运行时不得每次访问都调用 LLM 决策。
- AXIS 可以记录脱敏运行特征用于冷启动策略和规则优化，但默认不得记录页面正文、请求体、Cookie 或敏感查询参数。
- 节点来源的读写逻辑不要散落到多个页面。
- 线路组合规则不要在发布页、使用页重复实现。
- 发布认证逻辑不要复制到本机使用逻辑里。
- 本机节点属于节点来源，不是独立业务孤岛。
- 使用页只消费线路结果，不重新定义线路。
- 发布页只包装线路结果，不重新实现线路选择。
- 运行页只展示状态和修复入口，不承载配置主流程。
- 不为了向后兼容默认保留复杂旧概念；是否兼容需要先确认。

## 文案原则

前端用户可见文案必须面向用户动作，不暴露内部实现。

推荐表达：

- 添加节点来源
- 创建一条线路
- 选择这台设备要使用的线路
- 开启虚拟网口
- 发布给其他设备使用
- 复制连接信息
- 连接需要账号和密码

避免在用户文案中直接出现：

- egress group
- provider
- listener
- landing proxy
- transit route
- fallback group
- runtime reload
- 字段
- 权限
- 路由
- 入口
- 口径

底层字段可以沿用工程命名，但前端文案必须转成用户能理解的表达。

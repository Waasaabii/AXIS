# AXIS 核心概念

## 总模型

AXIS 的核心模型是：

```text
节点来源 → 线路组合 → 使用 / 发布
```

这个模型用于约束产品设计、前端页面、后端 API、配置渲染和文案表达。

## 节点来源

节点来源回答：可用于线路编排的节点从哪里来。

节点来源类型：

- 订阅：远程订阅，通常包含多个节点。
- 单个代理：用户手动添加的单个代理节点。
- 其他 AXIS：另一台 AXIS 发布出来的连接或订阅。
- 本机节点：当前设备创建出的节点服务。

本机节点创建完成后，应进入节点来源列表，与订阅、单代理、其他 AXIS 一起被线路组合消费。

## 上游模式与本体模式

AXIS 的节点来源必须区分“上游模式”和“本体模式”。这不是两个产品入口，而是同一节点来源模型下的不同责任边界。

### 上游模式

上游模式表示节点不是 AXIS 当前设备创建的，而是来自：

- 第三方订阅。
- 用户导入的单个代理。
- 其他 AXIS 发布的连接或订阅。

上游模式下，AXIS 不负责重新设计节点伪装。AXIS 的责任是：

- 完整导入上游节点。
- 保留原始分享链接和关键参数。
- 定时同步订阅源。
- 在节点失效时按冷却策略触发刷新。
- 维护上次成功快照。
- 按线路策略选择可用节点。
- 按目标客户端格式重新发布。

上游模式不能只保存 `server`、`port`、`password` 这类最小字段。否则 AXIS 再发布给 Shadowrocket、Mihomo 或其他 AXIS 时，可能丢失上游已经配置好的 SNI、Host、Path、ALPN 等能力，导致节点导入成功但无法连接。

### 本体模式

本体模式表示当前设备就是节点服务端，本机节点由 AXIS 创建。

本体模式下，AXIS 的责任是：

- 创建协议服务。
- 生成账号密码或等价认证。
- 配置监听地址和端口。
- 绑定线路作为出站路径。
- 生成 Trojan、Hysteria2 等协议所需连接信息。
- 检查域名、证书、TCP/UDP 可达性。
- 适配宝塔/nginx 或直接开放端口。
- 生成可给其他软件或其他 AXIS 导入的发布订阅。

本体模式不能要求用户自己拼接核心协议参数。用户可以选择域名、端口、访问方式和协议，AXIS 必须负责把这些选择转换成可用配置和明确检查结果。

## 本机节点

本机节点是当前设备提供的节点服务，而不是独立主导航概念。

本机节点可以支持多种协议，例如：

- HTTP
- SOCKS
- Trojan
- Hysteria2

协议只是节点来源的属性。创建本机节点时可以使用专门表单或向导，但创建后的管理归属于节点来源。

## 线路组合

线路组合回答：流量如何经过节点并到达最终出口。

线路组合可以包含：

- 初始代理：流量首先经过的节点或节点集合。
- 落地出口：流量最终出站的位置。
- 自动选择：按健康状态、延迟或策略选择节点。
- 手动选择：用户固定某个节点。
- 顺序容灾：按顺序尝试可用节点。
- 中转组合：多段路径组合。

线路组合是流量路径规则的唯一归属点。

## 使用

使用回答：这台设备自己怎么通过 AXIS 上网。

使用能力包括：

- 本地 HTTP/SOCKS 代理。
- 虚拟网口。
- 当前使用线路。
- 切换线路。
- 复制本机连接信息。
- 应用更改。
- 查看可用状态。

使用只消费线路组合结果，不重新定义线路。

## 发布

发布回答：如何把已有线路提供给其他软件、设备或 AXIS 使用。

发布形式包括：

- HTTP 代理入口。
- 订阅链接。
- AXIS 可导入连接。

发布项必须支持认证，默认要求账号密码或等价认证。

发布只包装已有线路，不创建节点来源，不重新编排线路。

## 宝塔/nginx 统一出口

AXIS 支持把域名、HTTPS 证书和公网统一入口交给宝塔或 nginx 管理。此时 AXIS 只负责本机服务端口、监听地址、认证、绑定线路和连接信息生成。

默认推荐：

```text
宝塔/nginx 公网入口 → 127.0.0.1:AXIS 本机端口 → AXIS 线路
```

监听地址必须由用户可选：

- `127.0.0.1`：仅本机可访问，适合宝塔/nginx 反代，默认推荐。
- `0.0.0.0`：允许其他设备直接访问，需要用户确认防火墙、认证和端口暴露风险。

## Trojan 与 Hysteria2 可用性

Trojan 和 Hysteria2 不能被描述为无条件一键可用。AXIS 可以快速生成配置，但必须检查和提示外部条件。

- Trojan：重点检查域名、证书、TCP 端口，以及宝塔/nginx 是否使用了合适的 TCP 转发方式。
- Hysteria2：重点检查 UDP 端口、云安全组、系统防火墙和协议安全参数。

普通宝塔 HTTP 反向代理不应默认用于 Hysteria2。Hysteria2 应按 UDP 端口直连或专门 UDP 转发处理。

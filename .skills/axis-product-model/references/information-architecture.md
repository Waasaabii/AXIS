# AXIS 信息架构

## 推荐主导航

AXIS 应随产品方向收敛为：

```text
首页
出口
规则
发布
诊断
系统
```

如果短期仍沿用旧导航，必须保证“创建本机节点”作为明确入口出现，不能继续隐藏在复杂线路表单里。

## 首页

首页是默认入口。

用户在这里完成：

- 查看这台设备现在能不能用。
- 查看当前默认出口。
- 查看本机代理或虚拟网口状态。
- 查看最近异常和推荐动作。
- 快速导入订阅。
- 快速创建本机节点。
- 快速生成推荐策略。

首页不应展示复杂协议字段或大段原始日志。

## 出口

出口承载所有节点来源、出口池和本机节点创建。

用户在这里完成：

- 添加订阅。
- 添加单个代理。
- 添加其他 AXIS。
- 创建本机节点。
- 管理本机 VPS 出口。
- 管理出口池和出口标签。
- 查看出口健康状态。
- 把创建完成的本机节点加入出口池。

“创建本机节点”必须是明确入口，不应只是隐藏在添加节点来源表单里的一个类型。

## 规则

规则承载直连、代理、出口选择和场景策略。

用户在这里完成：

- 创建自然语言规则。
- 查看 LLM 生成的规则草案。
- 测试、采用、调整或回退规则。
- 管理 ChatGPT、开发社区、下载、流媒体等场景。
- 管理异常时的出口切换策略。
- 查看冷启动策略和运行后优化建议。

规则页只管理可执行规则，不直接创建节点来源或修改协议运行配置。

## 发布

发布承载所有对外输出。

用户在这里完成：

- 发布 HTTP 代理。
- 发布订阅链接。
- 发布 AXIS 连接。
- 配置账号密码或等价认证。
- 控制访问范围。
- 复制连接信息。
- 选择发布给 Mihomo、Shadowrocket 或其他 AXIS 的格式。

## 诊断

诊断承载排障和状态查看。

用户在这里完成：

- 查看代理核心状态。
- 查看虚拟网口状态。
- 查看发布项状态。
- 查看最近错误、访问失败和操作记录。
- 查看 Cloudflare challenge、DNS、TLS、UDP 等诊断结果。
- 执行修复动作。
- 查看高级原始日志。

原始黑框日志只能作为高级详情，不应作为默认体验。

## 系统

系统承载低频管理能力。

用户在这里完成：

- 修改管理员密码。
- 管理高级配置。
- 管理核心版本。
- 检测当前代理核心支持的协议能力。
- 管理宿主集成。
- 管理 LLM 网关配置。
- 管理隐私、运行特征记录和数据清理。

## 旧导航映射

旧导航到新导航的映射：

```text
使用 → 首页
线路中的节点来源 → 出口
线路中的线路组合和规则 → 规则
发布 → 发布
运行 → 诊断
系统 → 系统
```

## 不推荐的信息架构

不要把以下技术对象默认并列为一级导航：

- 订阅与节点
- 出口线路
- 中转线路
- 本地代理
- 本机节点
- 运行状态
- 操作记录

也不要把“本机节点创建”隐藏成节点来源表单的一小块。它必须在首页快捷动作或出口页中被用户明确看到。

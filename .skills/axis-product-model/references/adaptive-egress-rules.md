# 自适应出口规则与冷启动策略

## 核心定位

AXIS 替代传统代理客户端的关键，不是重新做一个节点选择界面，而是让用户用更少操作表达目标，由 AXIS 自动选择直连、代理和出口。

核心模型：

```text
用户偏好 / 节点信息 / 运行特征 → 规则草案 → 用户确认 → 固定规则运行
```

LLM 可以帮助 AXIS 理解用户自然语言、已有节点和运行特征，但不能在每次访问时参与运行时决策。LLM 输出必须是 AXIS 可消费的结构化规则草案，AXIS 根据草案生成固定规则，不让用户手工编写配置。

## 与 Clash Verge 类客户端的差异

传统客户端通常要求用户自己完成：

- 判断是否直连。
- 选择代理节点。
- 选择出口。
- 手写域名规则。
- 手动切换场景。
- 根据失败现象判断原因。

AXIS 的目标是：

- 用户表达偏好。
- AXIS 生成可执行规则。
- 运行时自动选择出口。
- 异常时按固定规则调整。
- 用户只确认关键规则和风险动作。

## 运行时不得依赖 LLM

LLM 是规则编译器，不是运行时决策器。

正确流程：

```text
用户文字规则 / 冷启动输入 / 运行特征
  ↓
LLM 生成规则草案
  ↓
AXIS 测试和解释规则
  ↓
用户确认
  ↓
AXIS 固化为固定规则
  ↓
运行时由 AXIS 规则引擎执行
```

错误流程：

```text
每次连接事件 → LLM → 决定出口
```

禁止每次流量命中都调用 LLM。原因：

- 延迟不可控。
- 成本不可控。
- LLM 输出不稳定。
- 隐私风险高。
- LLM 网关异常时不能影响代理运行。

## 自然语言规则

用户可以用自然语言描述偏好，例如：

```text
linux.do 被 Cloudflare 拦时不要走 VPS，优先走香港或日本出口。
ChatGPT 走能解锁的节点，失败后先试新加坡，再试日本。
下载优先走低倍率节点。
公司网站直连。
Hysteria2 不稳定时切到 Trojan 出口。
```

LLM 将自然语言转换成规则草案，AXIS 再让用户确认。

如果一句话信息不足，AXIS 不应硬猜，应生成待补充项，例如：

- 作用范围。
- 优先地区。
- 自动切换还是提醒。
- 失败阈值。
- 是否排除 VPS。
- 规则有效期。

## 出口规则而不是全局切代理

AXIS 应优先切换“出口/落地路径”，不是简单全局切代理。

示例：

```text
linux.do → 香港/日本订阅出口
chatgpt.com → 新加坡解锁出口
netflix.com → 美国流媒体出口
下载站 → 低倍率出口
公司网站 → 直连
普通流量 → 默认出口
```

入口、本机代理、虚拟网口可以保持不变。变化的是目标域名、目标分类或异常场景对应的出口选择。

## 运行特征记录

AXIS 应在运行时记录必要特征，用于后续规则生成和策略优化。

可以记录：

- 目标域名。
- 目标分类。
- 当前入口。
- 当前出口。
- 出口标签。
- 节点来源。
- 协议。
- 连接结果。
- DNS 结果。
- TCP/TLS/UDP 检查结果。
- HTTP 状态码。
- 可识别风控信号，例如 Cloudflare challenge。
- 延迟。
- 失败次数。
- 切换前后的结果。
- 用户是否手动切换过。
- 用户是否确认过某条规则。

默认不记录：

- 页面正文。
- 请求体。
- Cookie。
- 登录信息。
- 完整 URL 查询参数。
- 私密路径。

## 特征聚合

发送给 LLM 的不应是原始日志，而应是 AXIS 聚合后的摘要。

示例：

```json
{
  "domain_profile": {
    "domain": "linux.do",
    "category": "developer_community",
    "last_24h": {
      "vps_156": {
        "success": 0,
        "cloudflare_challenge": 5,
        "avg_latency_ms": 420
      },
      "hk_subscription": {
        "success": 4,
        "cloudflare_challenge": 0,
        "avg_latency_ms": 260
      },
      "jp_subscription": {
        "success": 3,
        "cloudflare_challenge": 0,
        "avg_latency_ms": 310
      }
    }
  }
}
```

LLM 基于摘要生成规则草案，AXIS 负责校验和执行。

## 冷启动策略

首次导入节点或没有运行记录时，AXIS 可以使用已有节点信息生成初始策略草案。

冷启动输入包括：

- 节点名称。
- 节点来源。
- 协议。
- 地区标签。
- 倍率标签。
- 解锁标签。
- 测速结果。
- 可用性检查结果。
- 订阅信息类条目识别结果。
- 本机 VPS 标签。
- 用户选择的客户端和使用方式。

LLM 可以基于这些信息生成初始规则，例如：

- 日常访问优先健康和低延迟。
- AI 网站优先解锁节点。
- 开发社区优先香港或日本节点。
- 下载优先低倍率节点。
- 本机 VPS 作为默认出口，但遇到 Cloudflare challenge 时避开。
- 信息类节点和客户端提示节点不参与出口选择。

冷启动规则必须作为草案展示给用户，不能默认把高风险规则全部自动启用。

## 运行后优化

冷启动策略只是初始方案。AXIS 运行一段时间后，应基于真实访问特征优化规则。

推荐闭环：

```text
已有节点 → LLM 生成初始策略
  ↓
运行记录 → 聚合出口表现
  ↓
LLM 生成优化草案
  ↓
用户确认
  ↓
AXIS 固化规则
```

## 规则草案输出

LLM 输出应是结构化规则草案，例如：

```json
{
  "id": "linuxdo-cloudflare-avoid-vps",
  "confidence": 0.92,
  "scope": "domain",
  "when": {
    "domain": "linux.do",
    "error_type": "cloudflare_challenge",
    "current_egress_tags": ["vps"]
  },
  "then": {
    "action": "set_domain_egress",
    "prefer_egress_tags": ["HK", "JP", "subscription"],
    "exclude_egress_tags": ["vps"],
    "ttl": "24h"
  },
  "reason": "过去 24 小时 linux.do 经由 VPS 出口多次触发 Cloudflare challenge，而香港/日本订阅出口成功。",
  "missing_fields": [],
  "requires_confirmation": true
}
```

AXIS 必须校验：

- 规则作用范围合法。
- 标签存在。
- 候选出口存在。
- 候选出口健康。
- 用户未禁用该出口。
- 规则不会覆盖更高优先级规则。

## 流式规则生成

自然语言规则、冷启动策略和运行后优化可以使用 LLM 流式输出。

流式过程用于展示：

- 正在理解用户规则。
- 正在读取出口池和运行特征摘要。
- 正在识别缺失条件。
- 正在生成规则草案。
- 正在准备测试建议。

最终必须输出完整结构化规则草案。AXIS 校验通过后，才允许生成待确认规则。

禁止流式中间结果直接改变出口选择、写入规则或影响当前流量。

## 用户确认与测试

规则启用前，应向用户展示：

- AXIS 理解了什么。
- 将影响哪些网站或场景。
- 将优先使用哪些出口。
- 是否会自动切换。
- 规则有效期。
- 可以如何回滚。

用户可以选择：

- 采用。
- 调整。
- 仅测试一次。
- 放弃。

高风险规则默认需要确认。低风险规则可以在用户开启自动模式后自动采用。

## 规则执行

规则固化后，运行时由 AXIS 规则引擎执行。

运行时输入：

- 目标域名。
- 目标分类。
- 当前出口。
- 当前出口标签。
- 连接结果。
- 异常类型。
- 候选出口健康状态。

运行时输出：

- 直连。
- 使用默认出口。
- 使用指定出口池。
- 临时切换某域名出口。
- 提醒用户确认。
- 回退到上一规则。

## 安全与隐私

自适应出口规则必须遵守隐私边界：

- 默认只记录连接特征，不记录内容。
- 默认只向 LLM 发送聚合摘要，不发送原始日志。
- 敏感域名可允许用户加入不记录列表。
- 用户可以关闭运行特征记录。
- 用户可以清空历史特征。
- 用户可以关闭 LLM 规则生成。

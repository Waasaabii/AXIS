# 本机节点创建体验与 LLM 辅助方案

## 核心定位

本机节点创建是 AXIS 的核心能力之一。它表示“把当前设备/VPS 变成可被自己、其他设备或其他 AXIS 使用的节点”。

创建本机节点不能隐藏在普通表单里，应作为用户能明显看到的创建入口。

推荐入口：

```text
出口 → 创建本机节点
首页快捷动作 → 创建这台设备的节点
```

## 创建目标

创建前先让用户选择目标，而不是直接填写技术字段。

常见目标：

- 给这台设备自己使用。
- 给手机或其他电脑使用。
- 给其他 AXIS 使用。
- 作为默认出口。
- 作为备用出口。
- 同时创建兼容 TCP 和高速 UDP 节点。
- 创建后发布给 Shadowrocket、Mihomo 或其他 AXIS。

用户目标用于决定后续默认协议、发布格式、检测项和规则草案。

## 向导流程

推荐流程：

```text
选择目标
  ↓
检测当前设备环境
  ↓
选择或生成创建方案
  ↓
AXIS 固定配置生成
  ↓
端口、证书、TCP/UDP 可达性测试
  ↓
用户确认采用
  ↓
加入出口池
  ↓
生成发布连接和初始规则草案
```

不要把创建节点做成一次性长表单。复杂项应按步骤展开。

## LLM 的作用

LLM 可以辅助生成“创建方案草案”，但不能直接生成运行配置或直接启用节点。LLM 输出必须是 AXIS 可消费的结构化草案，由 AXIS 转换为临时配置、测试项和确认卡片，不要求用户手工照抄配置。

LLM 可以做：

- 根据用户目标整理创建方案。
- 根据设备环境判断缺少哪些条件。
- 建议创建单节点还是双节点组合。
- 解释 Trojan、Hysteria2、HTTP、SOCKS 在当前目标下的适用性。
- 建议发布给哪些客户端格式。
- 建议创建后加入哪些出口池。
- 生成初始规则草案，例如 VPS 默认出口、HY2 失败切 Trojan、Cloudflare challenge 时避开 VPS。

LLM 不可以做：

- 直接改 AXIS 运行配置。
- 直接修改 nginx、宝塔、防火墙或系统服务。
- 直接启用本机节点。
- 直接决定端口是否可用。
- 替代 AXIS 的 TCP、UDP、证书和域名检查。
- 绕过用户测试和确认。

## 固定配置执行

协议配置必须由 AXIS 的确定性逻辑生成。

AXIS 固定负责：

- 生成协议配置。
- 生成账号密码。
- 分配或校验端口。
- 配置监听地址。
- 绑定出口线路。
- 生成连接 URI 或订阅输出。
- 生成宝塔/nginx 配置片段。
- 检查本机监听。
- 检查 TCP/UDP 可达性。
- 检查证书和域名。

LLM 只参与方案草案，不参与配置执行。

## 核心支持要求

创建本机节点必须依赖当前代理核心的服务端能力。AXIS 不能因为 LLM 生成了方案草案就承诺某协议可创建。

创建前必须确认：

- 当前核心是否支持该协议出站。
- 当前核心是否支持该协议入站或 listener。
- AXIS 是否有对应创建模板。
- AXIS 是否能生成客户端连接信息。
- AXIS 是否能执行必要测试。

如果核心只支持出站，不支持入站或 listener，则该协议最多只能用于“本机使用上游节点”，不能创建当前设备作为该协议节点。

如果用户单独升级了 Mihomo，AXIS 应重新检测核心能力。检测到新能力后，可以通过 LLM 生成创建模板草案，但仍必须测试通过并由用户确认后才能启用。

## 环境检测输入

创建前 AXIS 应采集：

- 操作系统。
- 当前公网 IP。
- AXIS Web 监听地址。
- 是否检测到宝塔/nginx。
- 80/443 是否被占用。
- 推荐端口是否可用，例如 39013/tcp、39014/udp。
- 域名是否解析到当前 VPS。
- 证书是否存在、是否匹配域名。
- 云安全组或系统防火墙是否可能阻断端口。
- 当前已有节点来源和出口池。
- 当前用户希望支持的客户端。

这些信息可以脱敏后提供给 LLM，用于生成方案草案。

## 方案草案结构

LLM 输出应是结构化方案草案，例如：

```json
{
  "goal": "给手机和其他 AXIS 使用当前 VPS",
  "recommended_plan": "trojan_and_hysteria2",
  "nodes": [
    {
      "protocol": "trojan",
      "role": "兼容 TCP 出口",
      "listen": "127.0.0.1",
      "port": 39013,
      "external_host": "axis.example.com",
      "publish_formats": ["mihomo", "shadowrocket"]
    },
    {
      "protocol": "hysteria2",
      "role": "UDP 高速出口",
      "listen": "0.0.0.0",
      "port": 39014,
      "external_host": "axis.example.com",
      "publish_formats": ["mihomo", "shadowrocket"]
    }
  ],
  "checks": [
    "确认 TCP 39013 可达",
    "确认 UDP 39014 可达",
    "确认证书匹配 axis.example.com"
  ],
  "initial_rules": [
    "默认出口使用 Trojan",
    "Hysteria2 可用时作为高速出口",
    "Hysteria2 失败时切回 Trojan"
  ],
  "requires_confirmation": true
}
```

AXIS 必须校验草案中的协议、端口、监听地址、域名和发布格式是否合法。

## 流式创建建议

创建本机节点时，LLM 应优先支持流式输出，用于展示环境分析和方案生成进度。

流式过程可以展示：

- 正在检测当前设备环境。
- 正在判断端口、域名、证书、TCP/UDP 风险。
- 正在生成创建方案草案。
- 正在生成测试项。

流式结束后，必须得到完整结构化方案草案。AXIS 只有在 schema 校验通过后，才能生成临时配置和测试项。

禁止在流式输出过程中直接写入节点来源、修改运行配置或启用本机节点。

## 测试与确认

创建流程必须包含测试步骤。

至少测试：

- 本机端口是否监听。
- TCP 端口是否可达。
- Hysteria2 UDP 是否可达。
- 域名解析是否正确。
- 证书是否匹配。
- 生成的连接是否能被 AXIS 反向解析。
- 生成的 Mihomo/Shadowrocket 输出是否保留必要字段。

测试通过后，用户确认采用。确认后才：

- 写入节点来源。
- 加入出口池。
- 生成发布项。
- 生成初始规则草案。

## 创建后的归属

本机节点创建完成后，必须进入节点来源和出口池，不应停留在独立功能里。

归属关系：

```text
本机节点 → 节点来源 → 出口池 → 规则 / 使用 / 发布
```

创建结果可以被：

- 本机使用。
- 发布给其他设备。
- 发布给其他 AXIS。
- 加入默认出口池。
- 加入备用出口池。
- 被自适应出口规则引用。

## 前端展示

创建入口应明确展示为：

```text
创建本机节点
```

不要只展示为：

```text
添加节点来源
local_node
监听配置
```

用户可见文案应表达用户能做什么：

- 把这台设备变成可用节点。
- 给手机或其他设备使用。
- 创建后生成连接信息。
- 创建后加入出口池。
- 测试通过后再启用。

技术字段应放在高级设置中。

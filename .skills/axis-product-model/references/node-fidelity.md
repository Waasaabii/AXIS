# 节点字段保真与发布适配

## 核心原则

上游模式下，AXIS 不重新设计节点伪装，但必须完整保留上游已经给好的连接能力。订阅导入后如果丢失关键字段，节点可能在 AXIS 内部或二次发布后无法连接。

节点字段保真是 AXIS 使用和发布上游节点的底线。

字段保真不是后期优化。只要 AXIS 支持“导入订阅 → 组合线路 → 再发布给其他客户端”，就必须先保证原始字段不丢。否则用户会被迫自己研究协议差异，这违背 AXIS 降低使用复杂度的目标。

当 AXIS 发现当前解析模型无法表达某些字段时，应：

- 保留原始分享链接。
- 保存未知字段或原始解析片段。
- 标记这些字段尚未完全适配。
- 在发布前提示可能风险。
- 允许 LLM 生成适配建议和临时规则草案。
- 让用户测试通过后再采用。

## 必须保留的内容

导入订阅或单节点时，应尽量保留：

- 原始分享链接。
- 协议类型。
- 节点名称。
- 服务器地址。
- 端口。
- 用户名、密码、UUID 或认证字段。
- TLS 开关。
- SNI / servername。
- peer。
- insecure / allowInsecure / skip-cert-verify。
- ALPN。
- 传输层类型，例如 ws、grpc、tcp、udp。
- WebSocket Host。
- WebSocket Path。
- gRPC serviceName。
- Reality、XTLS、fingerprint 等协议扩展字段。
- UDP 支持信息。

如果当前版本暂不理解某些字段，也应保存在扩展字段或原始节点结构中，避免二次发布时丢失。

## 上游模式处理方式

上游模式的默认策略：

```text
导入 → 保真保存 → 标准化索引 → 健康检查 → 线路选择 → 按目标客户端适配输出
```

不要在导入阶段擅自删除看起来“不常用”的字段。不要把节点强行简化成统一最小结构后再发布。

## 本体模式处理方式

本体模式下，AXIS 自己创建节点，因此必须生成完整连接信息。

例如：

- Trojan 需要正确的域名、证书、SNI、TCP 端口和认证信息。
- Hysteria2 需要 UDP 可达、认证信息、TLS/SNI 或协议要求的安全参数。
- HTTP/SOCKS 需要监听地址、端口和账号密码。

本体模式不能依赖用户手动补齐核心协议参数。

## 发布适配

同一个 AXIS 节点池需要按目标客户端输出不同格式。

至少应区分：

- Mihomo / Clash YAML。
- Shadowrocket URI 订阅。
- 其他 AXIS 可导入格式。

发布适配器负责把保真字段转换成目标客户端能识别的字段名和结构。

示例差异：

- Mihomo 可能使用 `skip-cert-verify`。
- URI 可能使用 `insecure` 或 `allowInsecure`。
- Trojan URI 可能需要 `peer` 和 `sni`。
- Hysteria2 URI 需要保留密码、端口、SNI 和安全参数。

## 信息类条目

部分订阅会把套餐信息伪装成节点，例如：

- 剩余流量。
- 到期时间。
- 重置天数。
- 客户端使用提示。

这类条目可以展示在订阅详情中，但不应参与：

- 本机使用。
- 线路组合。
- 健康检查。
- 对外发布为可用节点。

## 验证要求

新增或修改订阅解析、节点转换、发布输出时，必须验证：

- 原始字段没有被无意丢弃。
- Mihomo 输出仍可导入。
- Shadowrocket 输出使用 URI 格式时仍包含必要参数。
- Trojan、Hysteria2、VMess WS 等常见节点保留关键字段。
- 信息类条目不会被当作可用节点。
